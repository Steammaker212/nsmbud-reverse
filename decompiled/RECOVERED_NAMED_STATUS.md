# Recovered named functions

`main.i64` contains 47,158 functions. Only **2,920** of them carry a name; the rest are IDA auto-names
(`sub_`, `nullsub_`, `j_`, `thunk_`). Of those 2,920 named functions, the corpus already covered 2,436 — which is
good news, because it means the corpus's existing names came from the same source: 2,397 of the 2,400 shared names
sit at identical addresses in both, i.e. the corpus already adopted this naming.

The remaining **483 named functions were entirely absent from the corpus** — not renamed, not present at all. They
sat in address gaps the corpus extraction never covered.

## What was done

All 483 were decompiled from `main.i64` with Hex-Rays and are now in `decompiled/recovered/recovered_named.c`
(472 bodies; 11 have no recoverable signature). Hex-Rays produced genuine C++ for them — real class names, parameter
names, member access, and even override annotations:

    // Overrides: Actor : 0x60002F08
    void __fastcall StageActor::afterCreate(StageActor *this, unsigned int onCreateVal)
    {
      if ( onCreateVal == 2 ) { ... }
      Actor::afterCreate();
    }

## Converting them to the corpus dialect

The corpus is C. Four mechanical rewrites were needed, each found by measurement:

| step | effect on error count |
|---|---:|
| include `nsmbudx_prelude.h` | 1,999 → 1,059 |
| flatten every `A::B` qualifier to `A_B` | 1,057 → 617 |
| declare missing data symbols and opaque types | 617 → 244 |

`this` is rewritten to the first parameter. An earlier version took the *last* parameter and produced 110
"undeclared identifier 'v'" errors; that is recorded here because the mistake is easy to repeat.

## Current state: 244 errors, and why they stop here

The remainder are not mechanical:

| count | error |
|---:|---|
| 97 | `must use 'struct' tag to refer to type X` |
| 44 | `no member named X in Y` |
| 39 | `member reference base type X is not a structure or union` |
| 30 | `expected expression` |
| 17 | `redefinition of X` |
| 7 | `conflicting types for X` |

These need real struct definitions for the actor and engine classes (`StageActor`, `nn_mii_ParamCharInfoAccessor`,
`sead_IDisposer`, …). The corpus has no such definitions because its own functions never dereferenced these types —
they passed opaque pointers. Producing those structs means recovering layout from the binary, which is a separate
piece of work, not a formatting fix.

The bodies are kept rather than dropped: the code is correct and readable, and it becomes compilable as soon as the
structs exist. `decompiled/include/nsmbudx_recovered_deps.h` is generated by
`scripts/declare_recovered_deps.py` and holds the 79 data-address macros and 20 opaque type declarations these
bodies need; it is merged additively on each run, because rewriting it from the current error list made the count
oscillate between 617 and 245.
